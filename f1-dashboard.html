F1 Performance Dashboard

An interactive Tableau dashboard exploring lap-by-lap pace, tire strategy, and sector performance across the 2025 Formula 1 season — built on real race telemetry pulled and cleaned with Python.

RoleSolo project
Races covered7 (2025 season)
ToolsPython (FastF1, Pandas) · Tableau Public

01The problem

Broadcast graphics show who's fastest, but rarely why. This dashboard was built to answer a more specific question: across a race weekend, which drivers were genuinely fastest on pace once tire age and strategy are accounted for — and where exactly on track, sector by sector, is time actually being won or lost.

02The data

Built on real 2025 F1 telemetry pulled directly from the sport's official timing archive via the FastF1 Python library, covering seven races chosen for variety of circuit type: Bahrain, Monaco, Great Britain, Belgium, Italy, Singapore, and Abu Dhabi. Each race contributes roughly a thousand lap-level rows, capturing sector times, tire compound, stint number, and finishing position for every driver.

FastF1 APITidy CSV output~1,000 rows / race

03Approach

The build split cleanly into a data layer and an analysis layer:

  • Pulled lap-by-lap telemetry with a Python/FastF1 notebook, converting raw timedelta fields into clean numeric seconds
  • Filtered out pit-stop and formation laps so pace comparisons reflect genuine racing, not pit-lane transit time
  • Built four linked Tableau views — lap pace, tire strategy, sector-by-sector deltas, and race results — unified by a single race selector
  • Designed a custom color system using official team livery colors for driver identification, with a lighter/darker split so teammates stay distinguishable, plus dash-pattern-by-teammate as a second layer of differentiation
Key decision

Rather than showing all 20 drivers' lap times by default, the dashboard opens on a curated 3-4 driver comparison with the rest available through an interactive filter. Twenty overlapping lines is technically complete but practically unreadable — the smaller default is a deliberate trade-off for what a first-time viewer can actually parse at a glance.

04Findings & outcome

The sector-delta view makes tire strategy visible in a way lap time alone doesn't: drivers running longer stints on Hard tires consistently lose time in the opening sector but claw it back in higher-speed sections once the tire window opens up. If this were feeding a live strategy call, the clearest takeaway is that stint length should be tuned to sector-specific characteristics rather than treated as a single track-wide decision.

05Reflection

Given more time, the next iteration would add a predictive layer — using the sector/tire relationship above to actually forecast optimal pit windows rather than just visualizing what already happened. I'd also automate the data pull to run after each race weekend instead of pulling a fixed set of races manually.
